# ADR-008: Auth Hook Error Contract — `Error | null`, Not `string | null`

## Status: Accepted

## Date: 2026-06-18

## Context

Auth hooks (`useRegister`, `useLogin`) call `toast.error()` in the calling
form component on failure. Their error sources differ:

- `useLogin` has one source — `signInWithPassword()` returns
  `{ error: AuthError | null }` directly from supabase-js.
- `useRegister` has two — a pre-signup `nickname` uniqueness check (ADR-007,
  a plain app-level check with no Supabase error behind it) plus
  `signUp()` itself, which does return an `AuthError`.

Mixing a hand-written string (`"Nickname already taken"`) with `AuthError`
in the same return type broke `error.message` in `RegisterForm`
(`Property 'message' does not exist on type 'string'`). Collapsing both
branches to `string | null` fixed that but made `useRegister` inconsistent
with `useLogin` — `toast.error(error)` then failed for `LoginForm`, since
`AuthError` isn't a plain renderable value.

Two hooks doing the same job need one shared contract, not two.

## Decision

All auth hooks — `useRegister`, `useLogin`, and future
`useForgotPassword`/`useUpdatePassword` — return `{ error: Error | null }`.

`AuthError` extends `Error`, so Supabase errors satisfy this contract
unchanged. Hand-written errors (the nickname check) are wrapped:

```ts
// hooks/use-register.ts
if (existing) {
  return { error: new Error("Nickname already taken") };
}
const { error } = await supabase.auth.signUp({
  email,
  password,
  options: { data: { nickname } },
});
return { error }; // AuthError, already an Error
```

Every form reads failure the same way regardless of source:

```ts
if (error) toast.error(error.message);
```

## Alternatives Considered

**Collapse both hooks to `string | null`**

- Rejected: throws away the real `AuthError` object (status, code) for no
  benefit, and doesn't fix `useLogin`/`toast.error()` without the same
  transform applied there too

**Cast the nickname error to `AuthError`**

- Rejected: resulting object only has `.message` — the cast lies to the
  type system about fields (`status`, `code`) that don't actually exist

**Fix `LoginForm` locally, leave contracts inconsistent**

- Rejected: every future auth hook would need to guess which contract to
  follow instead of having one documented standard

## Consequences

- `use-register.ts` — nickname check wraps in `new Error(...)`; `signUp()`
  branch passes `error` through unchanged
- `use-login.ts` — unchanged, already conformant
- `register-form.tsx`/`login-form.tsx` — both read `error.message`
- Every future auth hook returns `{ error: Error | null }`, no exceptions
