# ADR-004: Global Client State — Zustand over Context, and Auth Gating Model

## Status: Accepted

## Date: 2026-06-17

## Context

The player (v0.3) already needed global, client-side, cross-component state
(`activeId`, queue, volume) with no natural single owner in the component
tree. The same shape of problem was about to repeat for v0.2 Auth — a Sign
In modal needed to be triggerable from anywhere (navbar, a gated "like"
action, future settings entry point), and v0.8's planned `useUser` would
need to expose the current user to components with no shared parent.

At the same time, the default Supabase middleware boilerplate in `proxy.ts`
(redirect everything except `/auth`) needed to be reconsidered against the
actual UX target — a SoundCloud-style public/private split where most of
the app (`/`, `/feed`, search, player) is publicly browsable, not gated
behind a route-level redirect.

## Decision

All global, client-side, cross-component state in this project uses
**Zustand**, not React Context. This applies to:

- `hooks/use-player.ts` — already implemented (v0.3)
- `hooks/use-auth-modal.ts` — Sign In modal visibility, triggered from navbar,
  `LikeButton`, `SaveButton`, and any other gated action (v0.2)
- `hooks/use-user.ts` — planned for v0.8

Context remains acceptable only for state that is genuinely scoped to a single
component subtree with few consumers (e.g. a multi-step form) — not for
app-wide singletons.

### Auth gating model (v0.2)

This decision also fixes how auth-gating works across the app, replacing the
unmodified Supabase middleware boilerplate in `proxy.ts`:

- **Middleware (`proxy.ts`)** — only for fully private routes with no public
  variant: `/account/*`, `/upload`. Unauthenticated users never see these
  pages; redirected before render.
- **`useUser` + `useAuthModal`** — for everything else. Most of the app
  (`/`, `/feed`, search, player, public profile viewing) is publicly
  accessible. Actions that require auth (like, save, manage songs, opening
  settings) open the Sign In modal via `useAuthModal().open()` instead of
  redirecting.

No route-based redirect to `/auth/login` is used for these actions — the
modal is the only entry point into the sign-in flow from a gated action.

## Alternatives Considered

**Context + Provider for auth modal and `useUser`**

- Idiomatic React, no extra dependency
- Rejected: unnecessary re-render cost once `user` and modal state coexist in
  a Provider; requires wrapping `layout.tsx`; inconsistent with the existing
  Zustand pattern already used for the player with no offsetting benefit at
  this scale

**Keep Supabase's default middleware redirect-everything-except-auth pattern**

- Zero extra code, copy-pasted from official docs
- Rejected: contradicts the actual UX (SoundCloud-style — feed, search, and
  player must be public); would block legitimate anonymous browsing on `/`
  and `/feed`

## Consequences

- One pattern for all global client state — easier to explain and audit in a
  portfolio context (single answer: "global state → Zustand", not "depends
  where")
- `proxy.ts` must be rewritten to scope its guard to `/account` and `/upload`
  only, instead of "everything except `/auth`"
- `useUser` (v0.8) is pre-decided as a Zustand store, resolved here rather
  than deferred
- Every gated UI action (like, save, settings entry point) must call
  `useAuthModal().open()` rather than performing a route redirect

## Update — 2026-07-28 (Account Settings Merged Into Public Profile)

`/account/me` is removed entirely — its one reason for existing as a
private route was that no public profile page existed yet at v0.7. Once
`/profile/[nickname]` (public, per this ADR's original model) was built
for v0.9 Social, `/account/me` became a second page rendering the same
avatar/bio/tracklist layout as `/profile/[nickname]`, just gated and
self-only. Two pages meant syncing markup by hand on every design change.

`/profile/[nickname]` now handles both cases via a server-computed
`isOwnProfile` check (`currentUser?.id === profile.id`):
self → `EditProfileDialog` (nickname/bio/avatar/password, tabbed);
other user → `FollowButton` + `CopyLinkButton`.

**`proxy.ts` matcher updated:** `/account/:path*` removed, only `/upload`
remains under middleware guard — `/account/*` no longer exists as a route
at all, so guarding it is moot. This narrows, rather than contradicts,
this ADR's original gating model: `/upload` still has no public variant
and stays middleware-gated; profile viewing/editing now fully lives in
the `useUser`/`useAuthModal` public-route model this ADR already
established for everything else.

`UserProfileButton`'s "Account settings" link now points to
`/profile/[nickname]` instead of `/account/me`.
