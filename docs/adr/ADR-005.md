# ADR-005: Email Confirmation Redirect — Supabase Native Verification Flow

## Status: Accepted

## Date: 2026-06-17

## Context

While testing the PKCE signup confirmation flow locally, `redirect_to` in the generated confirmation link consistently resolved to `site_url` instead of the value passed via `emailRedirectTo` in `supabase.auth.signUp()` — even with matching protocol/host, a correct wildcard in `additional_redirect_urls`, and a full local stack restart after each config change.

This was initially treated as an upstream Supabase behavior. The original implementation therefore introduced `app/auth/confirm/route.ts`, which called `verifyOtp()` and selected the post-verification destination based on `type`.

## Decision

Password-based signup confirmation uses Supabase's native email verification flow.

The application passes the intended destination through `emailRedirectTo`:

```ts
emailRedirectTo: `${window.location.origin}/auth/confirmed`,

Supabase handles token verification and redirects the user to /auth/confirmed.
The application does not implement its own signup token verification or parse redirect_to to determine the destination.
Update — 2026-10-07
The production signup flow was verified from the actual confirmation email link.
The generated link has the following structure:
/auth/v1/verify?token=pkce_...&type=signup&redirect_to=https://www.music-hub.pl/auth/confirmed

The flow is therefore:
useRegister
→ supabase.auth.signUp()
→ Supabase /auth/v1/verify
→ /auth/confirmed

app/auth/confirm/route.ts is not used by the signup flow. The current implementation relies on Supabase's /auth/v1/verify endpoint and the emailRedirectTo value passed by useRegister.
The original verifyOtp()-based implementation described above is no longer the active signup implementation.
If app/auth/confirm/route.ts is not used by another authentication flow, it is dead code and can be removed.
Consequences
- Signup confirmation uses Supabase's native /auth/v1/verify flow.
- useRegister defines /auth/confirmed through emailRedirectTo.
- Token verification is delegated to Supabase.
- app/auth/confirm/route.ts does not participate in signup confirmation.
- The application does not implement custom signup token verification.
- OAuth remains unaffected and uses its own redirectTo mechanism.
```
