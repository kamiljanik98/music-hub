# ADR-014: Search Suggestions — Song Titles, Not Search-Term Analytics

## Status: Accepted

## Date: 2026-07-23

## Context

SoundCloud's navbar search dropdown shows suggested _search phrases_
("slowed reverb tiktok", "slowed reverb gym") sourced from aggregated
query/trending analytics — not content that exists in their catalog.
Replicating this requires a search-term log + ranking system with no
equivalent data source here.

v0.6 Search needs a navbar dropdown regardless. The available data is
`songs.title` itself, not historical search queries.

## Decision

Suggestions are **song titles from the `songs` table**, not generated
search phrases. `hooks/use-search-suggestions.ts` queries `songs.title`
via `ilike`, debounced, limit ~8 — distinct from `getSongs()` (ADR-013),
which also matches `tags`/`genre`/`scale` for the actual results page.

Selecting a suggestion redirects to `/search?title=<selected title>`,
same as pressing Enter on typed input — the dropdown is a shortcut into
the same results page, not a separate content type.

## Alternatives Considered

**Log search queries, rank by frequency (SoundCloud-equivalent)**

- Matches the reference UX exactly
- Rejected: requires a query-log table, write on every search, and a
  ranking job — disproportionate for a portfolio project with no real
  traffic to rank

**No suggestions, plain input + Enter only**

- Simplest, zero extra hook/query
- Rejected: loses a visible, demoable UX feature or a portfolio review;
  live-filtered dropdown is a common junior-dev interview talking point
  (debounce, controlled input, race conditions)

## Consequences

- `useSearchSuggestions` is a narrower query than `getSongs()` — title
  only, no `tags`/`genre`/`scale` matching, no pagination
- Dropdown suggestion count is bounded by actual catalog size — sparse at
  portfolio scale, expected and acceptable
- If real usage data existed later, this could be swapped for a proper
  query-log approach without touching `getSongs()` or `/search`
